## Findings

### Critical

**F1 · R6 Domain Model Distortion — 数组的值模型没有完整保留 dtype/shape**

Symptom: `codec.py::_encode_array/_decode` 对 object 数组用 `tolist()` 和 NumPy
自动推断；对 structured dtype 保存 `str(dtype)`。已运行 JSON 往返复现：
`object` 元素为两个等长列表时 `(2,) -> (2,2)`；`empty((0,2), object) -> (0,)`；
零维 object 数组抛 `TypeError: 'int' object is not iterable`；`[('id','i4'),
('mass','f8')]` 的结构化数组解码抛 `TypeError: data type ... not understood`。

Source: *Domain-Driven Design* — Value Object；*Code Complete* — Defensive Programming。

Consequence: 成功保存不代表能读回；形状静默变化可能影响下游统计，新增后处理不能
把现有“支持 NumPy”解释为所有 dtype 无损。

Remedy: [BUG-0010](../work/BUG-0010/zh-CN.md) 固定 object 的形状和元素边界；
[BUG-0011](../work/BUG-0011/zh-CN.md) 保存 structured dtype 的可重建描述，
用 JSON 和 SQLite 重开验证，不把 unsupported dtype 原始内存当 payload。

### Warning

**F2 · R3 Knowledge Duplication — 缓存恢复未同步清理单元格错误**

Symptom: `sample.py::add` 成功会 `row.errors.pop(label, None)`，
`fill_from_store` 只赋值。手工设为缺失并保留此前错误后，缓存补回 `10.0`，
`errors` 仍是 `{'mass': 'RuntimeError: previous failure'}`。

Source: *The Pragmatic Programmer* — DRY（同一个“单元格成功”状态转换分散在两处）。

Consequence: 表格同时表现为成功与失败，报告可能误筛掉已有有效结果。

Remedy: [BUG-0012](../work/BUG-0012/zh-CN.md)，成功填充值时清掉该格错误，miss 保留。

**F3 · R6 Domain Model Distortion — 样本表丢失固定来源**

Symptom: `SampleRow` 只有 name/identity/values/errors；`add` 丢弃 `result.store_ref`，
`to_dict` 也不保存它。这是需求缺口，不是声称违反了已有 SampleTable 测试合同。

Source: *Domain-Driven Design* — Ubiquitous Language / Identity。

Consequence: 同一输入和计算刷新多次后，表值不能唯一对应某次保存版本；计算 key 不能
替代 pinned reference，值相同也不能证明来源相同。

Remedy: [FEAT-0005](../work/FEAT-0005/zh-CN.md)，保存每格 ref 与表级 backend 名称，
明确 session-only 和无 store 的空引用语义。

**F4 · R6 Domain Model Distortion — 运行记录不足以表达环境与选中位置的历史事实**

Symptom: `ProvenanceInfo` 是签名与时间；`ResultRecord.from_result` 同样未记录版本清单；
ORM Run 没有 environment 字段，input_location 外键指向可变 URI 元数据。

Source: *Domain-Driven Design* — Domain Model；*Software Engineering at Google* — Sustainability。

Consequence: 不能核实某次调用用了什么依赖环境；后改 URI 后，FK 也不是调用时路径的
不可变证据。不能把签名可重建等同于数值完全可复现。

Remedy: [FEAT-0006](../work/FEAT-0006/zh-CN.md) 记录调用时已知版本和位置快照，
区分缓存消费者环境与载荷生产者环境；不擅自把环境全量加入缓存键。

**F5 · R3 Knowledge Duplication — 多份设计对执行和存储边界给出相反指令**

Symptom: 2026-10-22 方案要求新 Artifact Store 与整体重建；V1 ADR-001/002 以及
已合并 FEAT-0001–0004 要求保留 ResultStore 和现有执行器。V1 早期审计仍称逻辑身份、
ORM、固定版本缺失；原 `.develop_notes/architecture_design_v2.md` 又称 arch.md 为空，
当前文件已经有内容。

Source: *The Mythical Man-Month* — Conceptual Integrity；*The Pragmatic Programmer* — DRY。

Consequence: 后续 agent 可能重复实现已完成内容，甚至删除本轮刚建立的能力。

Remedy: 本次新增 [统一设计入口](README.md)、[既有决策索引](decisions.md) 与需求映射；
旧方案增加历史标识。外部原稿保留，旧审计不再作为当前实现事实。

**F6 · R5 Dependency Disorder — 发行目标与依赖入口仍未一致**

Symptom: ADR-005 要求完整默认安装有 ORM 且有正式轻量路径；pyproject 仍只提供
optional `store` extra。源码导入隔离已实现，这和发行目标完成是两件事。

Source: *Software Engineering at Google* — Dependency Management。

Consequence: 用户按默认安装期待 ORM 时仍缺依赖；直接把 SQLAlchemy 改成硬依赖又
不能通过 extra 移除它，会破坏承诺的轻量安装入口。

Remedy: [SPIKE-0001](../work/SPIKE-0001/zh-CN.md) 准备发行方案与可验证构建实验，
负责人决定名称/归属后由 [TASK-0002](../work/TASK-0002/zh-CN.md) 落地安装矩阵。
