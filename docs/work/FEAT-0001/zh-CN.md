# FEAT-0001: 将结果存储引用固定到不可变版本

## 背景

现有 store 按计算键覆盖结果，重算后旧 store() 引用会读到新值。
用户批准 PR #36 后继续 V1 规划，并确认不需要旧数据库或缓存兼容迁移。

## 目标

固定引用保留原结果，read-through 使用最新成功保存版本，并由 Result.store_ref
返回实际保存或命中的版本。

## 非目标

ORM Run 表、逻辑快照登记、自动 GC、载荷去重、外部文件、迁移及分布式调度。

## 验收标准

- [x] 同键重算后，第一次保存的引用仍读取原值。
- [x] 当前查找和 list_refs 保持最新结果语义。
- [x] 版本列表、引用 JSON 和 SQLite 重开保留历史。
- [x] 缓存失效不删除历史；用旧固定引用取消缓存不得影响新版本。
- [x] 修改读取到的可变值不改变已保存版本。
- [x] 写入失败时，历史及缓存更新一并回滚。
- [x] 并发成功的 SQLite 写入保留全部已返回版本。
- [x] 引擎写入/命中/刷新返回准确 store_ref；无 store 或失败运行不虚构版本。
- [x] 身份、签名及版本不匹配在载荷解码前报错。
- [x] make check、make test-all 通过，记录红绿证据。

## 设计说明

见 [ADR-007](../../adr/0007-immutable-result-versions.md)。RecordRef 有可选
version_id 和独立 cache_key；store() 返回固定版本，list_refs() 仍列当前缓存。
delete() 仅取消缓存，传入固定引用时要求版本仍为当前；删除后固定版本 fetch/contains
仍有效。记录使用 v4，不做迁移。

## 测试计划

先写 tests/test_result_versions.py 并确认失败，随后实现共享语义及两个后端。
运行专项、分层、快速及完整测试，保留原有测试。版本插入后注入缓存写入失败，
验证旧缓存和旧版本不变，且不产生孤儿版本。

## 结果

已实现，基于 main 8f191b2。最初契约测试在实现前 25 项失败，扩展后的版本测试
37 项通过。make check：973 通过、1 跳过、3 未选中，ruff/mypy/文档检查均通过；
make test-all：976 通过、1 跳过。原有损坏记录测试暴露了当前记录的共享引用问题，
现内存读取和 SQL 后端一样，通过缓存选定版本后读取不可变记录。
相关回归测试 77 项通过，原有测试未修改。

用户已授权发布与合并。历史清理和 ORM 集成留待后续阶段，v4 按要求不做旧格式迁移。

## 待决问题

本阶段无待决问题。历史版本暂不自动清理，后续 ORM 管理 backend 和引用生命周期。
