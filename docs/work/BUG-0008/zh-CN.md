# BUG-0008: 中值滤波 constant 边界错误地引入零值

## 背景

PR #34 审查发现了既有边界问题，未纳入 BUG-0006 的逐轴补边修复。
`median_filter` 文档规定 constant 模式补 NaN，因此图像外的值不应参与中位数。
但全有效像素的 SciPy 快速路径和带 mask/非有限值的 NumPy 路径目前都会补零。

## 目标

让全有效图像与含无效像素的图像均遵守已有的 constant 模式契约。

## 实际行为

对 `[[10, 20], [30, 40]]` 使用 size=3、constant 模式，结果为四个零。
将右下像素改为 NaN 后，三个有效输出仍为零。

## 期望行为

第一组输入应输出四个 25；第二组应在各有效像素输出 20，无效中心保持 NaN。
样本只包含图像内有限且未被 mask 排除的像素；图像外表示没有样本，而非零值样本。

## 复现方式

```python
median_filter([[10., 20.], [30., 40.]], size=3, mode="constant")
```

## 非目标

其他边界模式（包括其偶数窗口行为）、通用 size 校验、大窗口性能重构、依赖变更及
calculator/store 架构调整。

## 验收标准

- [x] 正值和负值图像的角、边与内部结果匹配独立的裁剪窗口中位数参考。
- [x] 全有效、mask 和非有限值输入遵守同一 constant 语义；无效中心保持 NaN，
      输入不被修改。
- [x] 奇数/偶数方形或矩形窗口、单元素轴、空轴及全无效图像均正确。
- [x] ImageData 转发 constant 模式、保留几何/单位并记录操作参数。
- [x] 原有测试、make check 和 make test-all 通过，不放宽容差。

## 设计说明

其他模式下的全有效图像继续使用 SciPy 快速路径。非空 constant 输入统一经过
NaN-aware 窗口路径，调用 `np.pad` 时明确传入 `constant_values=np.nan`；
该参数不传给其他补边模式。不修改公共签名或已有文档要求，只修复契约违例。
constant 模式每轴前方补 `k//2`、后方补 `k-1-k//2`，与 SciPy 默认 origin=0 的
偶数窗口位置一致，并保持输出形状。对剩余真实样本取算术中位数；中间有两个样本时，
按现有 np.nanmedian 的行为取其平均值。

## 测试计划

1. 使用裁剪窗口构建独立参考，不复用 np.pad 或滑动窗口实现。
2. 在当前实现上运行新回归，记录预期失败。
3. 最小化修改执行路径与补边参数，重新运行专项测试。
4. 执行 make check 和 make test-all；独立审查；按维护者的持续授权发布并合并。

## 结果

constant 模式现统一使用 NaN-aware 窗口路径并明确补 NaN。
前后补边宽度在奇数和偶数窗口下均保持 origin=0 位置与原图形状。
空输入保留原有 SciPy 路径；其他模式保持原有执行路径。

- 红灯：原实现运行新增 constant 回归，**34 failed、2 passed、40 deselected**。
- 审查回归：新增六个空数组测试先失败，保留原有空数组路径后通过。
- 绿灯：smooth/ops/methods 专项 **132 passed**（新增 42 个用例）。
- `make check`：lint/mypy/文档通过；**908 passed、1 skipped、3 deselected**。
- `make test-all`：**911 passed、1 skipped**。
- 2x2 正值示例现全部输出 25；含一个无效像素时，有效像素输出 20，
  无效中心仍为 NaN。
- 两处公共接口文档明确了 constant 模式的样本排除及算术中位数。
  全有效 constant 输入也走窗口路径，因此现有的大窗口内存提示同样适用。
- 为已合并的 BUG-0002/0006/0007 补齐完成状态及 handoff，保留历史红绿证据，
  并遵守归档保留期。

验证环境：Linux / Python 3.11.9 / pynbody 2.8.0，项目 .venv。
